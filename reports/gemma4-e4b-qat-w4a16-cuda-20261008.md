### 재현한 오류와 수정

기존 oev의 Gemma 4 선택지 투영 경로는 `model.model(...)`을 직접 호출했습니다. compressed-tensors는 모델 최상위 forward pre-hook에서 packed 가중치를 역양자화하므로, 이 경로는 훅을 건너뛰고 `AttributeError: 'Linear' object has no attribute 'weight'`를 발생시킵니다. 실제 compressed-tensors 라이브러리로 압축한 작은 Gemma 4 모델에서 오류를 재현했습니다.

`src/oev/hf.py`에서 최상위 pre-hook이 있으면 정상 모델 forward를 호출하도록 수정했습니다. 첫 추론이 끝나면 역양자화 훅이 제거되고 이후 추론에서 선택지 투영 최적화를 다시 사용합니다. 회귀 테스트는 첫 추론이 훅을 실행하고 정상 전체 logits과 일치하는지, 이후에는 전체 vocabulary 투영을 건너뛰는지 검사합니다.

프로젝트에 `qat` extra를 추가했고 전체 테스트 25개가 통과했습니다. `uv lock --check`, `git diff --check`, 의존성 audit도 통과했습니다.

재실행 명령:

```powershell
uv sync --locked --extra hf --extra qat
uv run --locked --extra hf --extra qat oev --model google/gemma-4-E4B-it-qat-w4a16-ct --revision 6cd26aaa2357fb2bad8c51699a7558a4d1a965bb --device cuda --dtype bfloat16 --input examples/stress-challenges.jsonl --output results/gemma4-e4b-qat-stress-rerun.jsonl
```

로컬 진단 기록은 `results/gemma4-e4b-qat-cuda-events.jsonl`, 기본 예제 포함 18건의 결과는 `results/gemma4-e4b-qat-cuda.jsonl`, Windows 메모리 표본은 `results/gemma4-e4b-qat-windows-memory.json`에 있습니다. 결과 파일은 현재 `.gitignore`에 따라 로컬에 보관됩니다.
